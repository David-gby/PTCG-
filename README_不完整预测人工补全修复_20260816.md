# CardScope v0.8.2 不完整预测人工补全修复

更新日期：2026-08-16  
适用项目目录：`cardscope/`  
目标版本：`0.8.2`

## 1. 问题结论

截图中的卡牌外形规整，页面也已经显示人工外框四角和人工内框四线；失败并不是因为这张卡“无法标注”，而是审核保存顺序存在缺陷。

旧逻辑在读取人工修正结果之前，先检查模型原始预测是否同时含有外框和内框。只要原始模型缺少其中一项，就立即返回 `PREDICTION_INCOMPLETE`。因此即使标注员已经补齐全部几何数据，仍无法批准并写入训练池。

## 2. 修复内容

1. 原始外框和原始内框改为独立校验，单侧缺失不再提前中断审核。
2. 优先读取并严格校验当前页面上的人工外框四角和人工内框四线。
3. 只有“模型结果和人工结果合并后仍不完整”时，才继续返回 `PREDICTION_INCOMPLETE`。
4. 原始模型结果不完整但人工已经补齐时，网页会弹出二次确认，避免误把默认线写入训练池。
5. 批准后的标注会记录：
   - `prediction_incomplete_at_review`
   - `manual_completion.outer`
   - `manual_completion.inner`
   - `outer_source` / `inner_source`
6. 企业端直接确认仍保持严格：模型结果不完整时不能绕过人工审核。

## 3. 涉及文件

- `platform_app/service.py`
- `web/admin.js`
- `tests/test_platform_regressions.py`
- `VERSION`

本次不替换 `.pt` 权重，不改变 2026-08-13 已上线的内外框模型。它修复的是“检测部分缺失后，完整人工标注仍无法保存”的平台阻断问题。

## 4. 测试结果

本地执行：

```bash
python -m unittest discover -s tests -p 'test_*.py' -v
```

结果：9 项回归测试全部通过。新增测试覆盖“模型有外框但缺少内框、标注员补齐四角和四线、二次确认后成功保存”的截图同类场景。

## 5. 部署方法

推荐使用服务器现有 release 更新脚本：

```bash
sudo bash deployment/server/update_release.sh \
  /上传目录/cardscope_v0.8.2_20260816.zip \
  https://实际正式域名
```

部署不得覆盖服务器生产持久化目录。必须保留：

- `/var/lib/cardscope/platform_workspace/private/platform.sqlite3`
- `/var/lib/cardscope/platform_workspace/studio_data/`
- `/var/lib/cardscope/platform_workspace/private/access_links.json`
- 企业图片、训练池、账号和服务器 `.env`

## 6. 部署后验证

1. 打开一条显示 `PREDICTION_INCOMPLETE` 的待审核样本。
2. 确认或调整外框四角，并点击“应用外框并刷新内框图”。
3. 确认四条内框红线。
4. 点击“审核通过并加入训练池”。
5. 若原始模型缺少外框或内框，网页应显示全人工补齐确认框。
6. 确认后状态应变为“已批准”，并返回训练池样本编号。

如果人工四角或四线本身不完整，服务器仍会拒绝保存，这是预期的训练数据安全保护。
