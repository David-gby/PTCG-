# CardScope v0.8.4：预裁切卡牌检测修复

更新日期：2026-08-22  
流水线：`ptcg_outer_inner_pipeline_20260822_precropped_v1`

## 问题原因

旧服务器仍运行 `ptcg_outer_inner_pipeline_20260813_feedback_trained_v1`。
当上传图片已经裁到卡牌外框、背景很少或完全没有背景时，外框分割可能与
图像边界粘连，随后被几何安全门判为 `INVALID_KEYPOINT_GEOMETRY` 或
`OUTER_FRAME_NOT_DETECTED`。流水线因此在外框阶段退出，内框模型没有运行，
网页显示“未获得完整结果”。

## 本次修复

现在有两条互补路线：

1. 图片仍保留少量背景、只有一至两条候选边粘住图像边界时，沿用
   `outer_boundary_contact_recovery.py` 的全分辨率长边重定位；
2. 图片已经严格裁到整张卡牌时，新增
   `pre_cropped_card_recovery.py`。只有正常外框检测失败且整图比例接近
   63:88，才把四个图像角临时视为外框。这个候选不会立即通过；系统必须
   在630×880校正图中独立检测到印刷内框线内沿，并且宽高与企业确认的
   58×83 mm，即580×830 px一致，才返回完整结果。

第二阶段确认避免了把普通63:88竖图误识别成卡牌。内框置信度不足，或者
宽高残差超过32 px时仍明确失败，不会伪造居中度。

## 部署文件

本包为完整 `cardscope/` 项目目录，包含当前最新官方图+反馈历史权重，以及
这次预裁切兼容代码。推荐使用：

```bash
sudo bash /opt/cardscope/current/deployment/server/update_release.sh \
  /上传目录/cardscope_v0.8.4_20260822_precropped.zip \
  https://实际正式域名
```

若部署同学坚持原位更新，可解压后执行：

```bash
cd cardscope
sudo bash deployment/server/apply_v0.8.4_update.sh "$(pwd)"
```

两种脚本都不会覆盖 `/var/lib/cardscope/platform_workspace`。严禁手动覆盖
服务器数据库、企业图片、账号、训练池、`.env` 和访问凭据。

## 部署后验证

```bash
cat /opt/cardscope/current/VERSION
curl -fsS http://127.0.0.1:8765/api/platform/v1/health
```

若需要强制验证新分支，将一张已经裁好的卡牌图片放在服务器上，执行：

```bash
/opt/cardscope/venv/bin/python \
  /opt/cardscope/current/deployment/validation/run_precropped_smoke.py \
  --input /路径/预裁切卡牌.jpg \
  --output /tmp/cardscope_precropped_smoke \
  --device cpu
```

成功标准：`success=true`、`stage=complete`、
`pre_cropped_confirmed=true`，并生成 `outer_frame_overlay.jpg`、
`rectified_card.jpg`、`inner_frame_overlay.jpg` 和 `result.json`。
