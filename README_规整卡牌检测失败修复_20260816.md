# CardScope v0.8.3 规整卡牌检测失败修复

更新日期：2026-08-16  
流水线版本：`ptcg_outer_inner_pipeline_20260816_boundary_recovery_v1`

## 1. 现象与真实原因

目标图片中的卡牌清晰、接近竖直、四边完整，旧模型却返回：

`INVALID_KEYPOINT_GEOMETRY` → `PREDICTION_INCOMPLETE`

这不是标注问题，也不是模型没有识别到卡牌。旧外框分割置信度为
`0.968237`，但分割轮廓把左边整条线粘到了图像边界，生成的左上、左下
两个角点均为 `x=0`。原有几何保护正确拒绝了该候选，随后流水线直接
结束，透视校正和内框检测没有机会运行。

## 2. 修复方案

新增 `outer_boundary_contact_recovery.py`，仅在下列条件全部满足时运行：

1. 原外框错误必须为 `INVALID_KEYPOINT_GEOMETRY`；
2. 分割已检测到卡牌，且综合置信度不低于 `0.75`；
3. 面积和长宽比仍接近卡牌合理范围；
4. 一条或两条候选边的两个端点同时贴到图像边界；
5. 在原始高分辨率图上向内搜索时，必须检测到跨越大部分边长的强物理边缘；
6. 重定位后的四边形必须重新通过原有、未放宽的几何校验。

算法先对图像做轻度高斯去纹理，在 Lab 色彩空间沿候选边进行密集法向
扫描，以截尾均值、中位差、边缘支持率和峰值显著性共同判断真实物理边。
通过后，再交给既有四边高分辨率精修器完成最终贴合。证据不足时保持失败，
不会猜测坐标，也不会绕过人工审核。

## 3. 目标图片复测结果

- 修复前：外框阶段失败，左上/左下 `x=0`，内框未运行；
- 物理边重定位：左边从 `x=0` 移至 `x=60`；
- 四边精修后左边约为 `x=57.8`；
- 修复后：`stage=complete`；
- 外框置信度：`0.968237`；
- 内框四线：左 `23.804`、右 `604.970`、上 `27.360`、下 `842.720`。

- `server_diagnostics_20260816/patched_rectified_card.jpg`

## 4. 生产历史回放

对服务器 4016 份历史预标注做了只读扫描，其中 28 份属于相同的
`INVALID_KEYPOINT_GEOMETRY` 目标类型。使用完整新流水线重新推理：

- 24/28 完成外框、透视校正和内框检测；
- 其中 20 份明确由触边恢复分支救回；
- 4 份证据不足，仍保持外框失败并进入人工复核；
- 原本成功的样本不会触发该分支，坐标路径保持不变。

这说明修改提高了“规整卡牌但分割轮廓粘边”场景的召回率，同时保留失败
保护。它不是通过降低阈值换取通过率。

## 5. 测试

共 12 项自动回归测试通过，包括：

- 强长边证据下可恢复触边候选；
- 均匀图像没有独立边缘证据时继续失败；
- 非目标错误不受影响；
- 平台训练池导出、永久删除、列表滚动、人工补齐等既有回归测试。

## 6. 部署注意事项

本次没有替换 `.pt` 权重，新增的是受门控的推理恢复算法。更新时必须同时
替换：

- `ml_backend/ptcg_inference.py`
- `ml_backend/card_quality_processor/outer_boundary_contact_recovery.py`
- `ml_backend/model_manifest.json`
- `VERSION`

完整发布包也包含 v0.8.2 的平台审核修复。严禁覆盖服务器的
`platform_workspace`、SQLite 数据库、企业图片、账号、训练池和 `.env`。
