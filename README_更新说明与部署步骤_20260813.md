# CardScope v0.8.1 更新说明与部署步骤

更新日期：2026-08-13  
项目目录：`cardscope/`  
目标版本：`0.8.1`

## 1. 这个压缩包是什么

本包完全沿用服务器部署同学提供的项目目录形式：解压后只有一个完整的 `cardscope/` 项目根目录。代码、网页、模型和部署脚本均处于服务器项目原来的相对路径中，不再拆分成“应用 / 脚本 / 文档”三套重复目录。原包的 `.git/` 和 `ptcg` 远程仓库绑定也予以保留，部署同学解压后可以直接查看 `git diff` 或按其现有流程推送代码。

本包不包含生产数据库、企业账号、服务器企业图片、训练池数据、导出缓存或服务器运行日志。仅保留原 Git 仓库已经跟踪的旧示例上传文件，以保证工作树不会出现无关的删除状态。部署时必须继续使用服务器现有的持久化目录，不能用空目录覆盖生产数据。

## 2. 本次用户功能更新

1. 删除管理员网页上的自动训练功能和自动训练入口；相关 HTTP 路由不再对外提供。
2. “导出训练池数据”只导出已经人工批准并实际进入训练池的样本，不再混入历史数据。
3. 修复训练池超过 1000 条时导出不完整的问题，改为读取完整训练池。
4. 导出改为服务器临时文件流式下载，降低大数据导出时的内存占用，并修复导出失败。
5. 修复永久删除失效：永久删除反馈样本时同步清理数据库记录、原图、标注和对应训练池文件。
6. 修复反馈列表点击后自动滚回顶部的问题，选择样本后保留原滚动位置。
7. 保留“已批准退回待审核”和“标注管理员舍弃样本”的审核流程。

## 3. 本次模型更新

流水线版本：`ptcg_outer_inner_pipeline_20260813_feedback_trained_v1`

- 外框：更新反馈训练后的卡牌轮廓分割模型和四边精修模型；加入阴影风险、光度检查、几何质量门控和安全回退。
- 内框：更新为七通道 V5 四边精修器，并保留左上角商标 / 标题干扰专用回退。
- 内框左边界盲测平均误差由 `2.7584 px` 降至 `1.4367 px`。
- 新反馈测试集内框总体 MAE 由 `2.375 px` 降至 `1.626 px`。
- 外框新反馈测试集四角 MAE 由 `13.4095 px` 降至 `5.0686 px`。

完整模型与哈希信息见 `ml_backend/model_manifest.json`。

## 5. 服务器部署方法

以下命令假定服务器当前项目链接为 `/opt/cardscope/current`，服务名为 `cardscope`，持久化数据位于 `/var/lib/cardscope/platform_workspace`。如果实际路径不同，请通过脚本支持的环境变量调整。

> 重要：本项目 `.gitignore` 会忽略 `ml_backend/models/`。因此只执行 `git push / git pull` 不会把新的 `.pt` 模型权重传到服务器。推荐直接使用本 ZIP 和下方更新脚本；如果坚持走 Git，仍必须从本包手工同步 `ml_backend/models/`，再核对 `ml_backend/model_manifest.json` 中的 SHA-256。

### 推荐：沿用原项目的 release 更新方式

```bash
sudo bash deployment/server/update_release.sh /上传目录/cardscope_v0.8.1_20260813.zip https://实际正式域名
```

上面的 `deployment/server/update_release.sh` 使用服务器当前项目中的脚本，ZIP 路径指向本次上传的新包。脚本会自行解压 ZIP、建立新的 `/opt/cardscope/releases/0.8.1_时间戳/`、切换 `/opt/cardscope/current`，并保留旧 release 以便回滚。这是最符合原服务器项目结构的更新方式。

### 备用：在 current 上热更新

只有部署同学明确希望原位替换时才使用：

```bash
unzip cardscope_v0.8.1_20260813.zip
cd cardscope
sudo bash deployment/server/apply_v0.8.1_update.sh "$(pwd)"
```

热更新脚本会自动执行：

1. 将现有 `VERSION`、`web/`、`platform_app/`、`ml_backend/` 备份到 `/opt/cardscope/backups/`。
2. 仅更新网页、平台代码、算法代码和模型。
3. 不覆盖 `/var/lib/cardscope/platform_workspace` 中的生产数据。
4. 重启服务并检查 `http://127.0.0.1:8765/api/platform/v1/health`。
5. 健康检查失败时自动恢复旧版本程序文件。

热更新时如服务器路径不同，可使用：

```bash
sudo CARDSCOPE_CURRENT_LINK=/实际/current \
     CARDSCOPE_WORKSPACE=/实际/platform_workspace \
     CARDSCOPE_SERVICE=实际服务名 \
     CARDSCOPE_VENV_PYTHON=/实际/venv/bin/python \
     bash deployment/server/apply_v0.8.1_update.sh "$(pwd)"
```

## 6. 部署后检查

```bash
cat /opt/cardscope/current/VERSION
curl -fsS http://127.0.0.1:8765/api/platform/v1/health
sudo systemctl status cardscope --no-pager
sudo journalctl -u cardscope -n 100 --no-pager
```

网页人工检查：

1. 管理员页面不再显示自动训练。
2. “导出训练池数据”可以下载 ZIP；ZIP 内 `export_manifest.json` 应显示：
   - `data_scope = approved_training_pool_only`
   - `historical_data_included = false`
3. 永久删除测试样本后，该样本从列表、数据库和训练池导出中消失。
4. 在反馈列表向下滚动并连续选择样本，列表不再跳回顶部。
5. 随机检查若干卡牌，确认网页模型版本为 `ptcg_outer_inner_pipeline_20260813_feedback_trained_v1`。

## 7. 严禁覆盖的生产内容

部署时不得删除或覆盖：

- `/var/lib/cardscope/platform_workspace/private/platform.sqlite3`
- `/var/lib/cardscope/platform_workspace/studio_data/`
- `/var/lib/cardscope/platform_workspace/private/access_links.json`
- 服务器现有企业图片、训练池文件和账号配置
- 服务器 `.env` 或 systemd 中保存的密钥、管理员密码、域名等环境变量

本压缩包内没有上述生产数据。若服务器的持久化目录位于项目目录内，部署前必须先单独备份并在更新后原位保留。
